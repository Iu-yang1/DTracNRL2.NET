# RC-3040S 固件第五阶段：AT 控制入口、TCP 管理端口、速度数值和自动加减速证据

分析日期：2026-10-24。样本：`RC_3040S_67S_8H_251217(1)_firmware_8051.bin`，SHA-256 `59f5114c0289fb0f273aba50b5987688a27bf88e1034a577a38c46bb45ba019f`。地址为独立 8051 代码映像地址。工作仅做静态二进制验证，**没有进行 TCP/UDP 实际设备通信、设备重启、写入 EEPROM 或驱动电机**。

## 1. 重要结论：TCP Socket 0/60030 存在管理数据路径

- `0x920C` 初始化例程：在 `0x9212` 加载端口 `R4:R5=EA:7E` = **60030**，`R7=0` (Socket 0)，`0x9217 LCALL 0x86E8`。`0x86E8` 同样用于 Socket 3 TCP/60020 初始化。这里的 TCP 属性根据共享初始化函数可强烈推定，后续应由真实抓包验证。
- 主循环 `0x84D1 -> 0x993A`，其中 `0x993D -> 0x920C` 初始化 Socket 0、`0x9940 -> 0x912D` 轮询 Socket 0 接收。
- 有条件的应用数据处理链：`0x9157 -> 0x9856 -> 0x89D9 -> 0x8A1B -> 0x6240 -> 0x62DA -> 0x5CE1 -> 0x5DB7 -> 0x3863`。`0x89D9` 在进入解析前有数据位标志判断，`0x6240` 调用 `0x3F6B` 按数据类型分流，**不能断言把裸 ASCII AT 命令直接写入 TCP/60030 就会生效**。
- 第二条 AT 入口 `0x84B9 -> 0x75E6 -> 0x7652 -> 0x3863`。其中 `0x75E6` 使用 XDATA `0x0D80..0x0D83` 队列，生产者与芯片外设中断相关（`0x6D30 -> 0x7954 -> 0x78DC`）。物理 UART 引脚、波特率以及可否外部直接配置仍需追踪；不应把它无证据地称为 TCP/60020。
- **两个直接 AT 调用位置恰好为 `0x5DB7` 和 `0x7652`**（全镜像对应三字节 `LCALL` 模式扫描）。

## 2. 跟普通 GS-232/NRL2 的区别

| 通道 | 固件证据 | 对 SDK 的意义 |
|---|---|---|
| TCP Socket 3 / **60020** | `0x7CA8..0x7CAE` 端口 `EA74`，`0x8822 -> 0x885A -> 0x3433` | 证据支持普通 GS-232 控制，不应默认开放 EEPROM/AT 配置 |
| TCP Socket 0 / **60030** | `0x9212..0x9217` 端口 `EA7E`，`0x9157 -> 0x9856 ... -> 0x3863` | 有经过封装/判断的管理指令通路，需恢复其帧语法后才能用于 SDK |
| UDP Socket 2 / **60059** | `0x915B` + `0x8E0A` | 局域网 ping/pong 发现；当前无证据为 AT/运动指令入口 |
| UDP Socket 7 / NRL2 | `0x482F -> 0x4A3A -> 0x3433` | Type 5 送 GS-232，不等于可直接执行 AT 配置 |
| 中断/外设接收队列 | `0x75E6 -> 0x7652 -> 0x3863` | 存在另一个 AT 命令入口，但不能猜测具体电气 UART 类型 |

`0x883C..0x8852` 中，Socket 3 数据首字节 `0x55` 时调用 `0x84F0`；其他情况进入 `0x3433`。**首字节 `0x55` 的分支不是已证明的 AT 通路**。

## 3. 速度参数：五位十进制、16 位存储，但物理上下限未知

固件两轴分别在 `0x3BE0`（AZ）和 `0x3C08`（EL）匹配 `AT+AZ_SPD=` / `AT+EL_SPD=`。

- 两条路径都以 `R7=0x0A` 调用 `0x720E`，该函数从缓冲区固定偏移 +10…+14 取 **五个字符**，计算权重依次 10⁴、10³、10²、10、1（汇编常数 `0x2710`, `0x03E8`, `0x0064`, `0x000A`）。因此建议序列化成 **五位补零的 ASCII 数字**，如 `AT+AZ_SPD=00300\r`；原 SDK 用 `AT+AZ_SPD=300\r` 对固定位置读取不安全。
- 在 `0x3BF1` / `0x3C19` 写入 XDATA 16 位值 `0x102A:2B` / `0x102C:2D`，调用 `0x9500` 持久化，继而调用 `0x7A44` / `0x7ABB` 更新实际速度相关硬件寄存器。保存过程说明设置可能写入非易失存储，不能作为无害探测命令反复发出。
- `0x720E` 路径未见对每个输入字符的显式十进制有效性校验；五位数可能大于 16 位范围发生截断。SDK 因此应只构造 00001..65535 五位格式，但**该范围是 SDK 的编码/溢出保护范围，不是被证实的机械安全范围或厂商推荐值**。
- `0x7A44..0x7ABB` 包含定时/计数相关 SFR 写入（例如 `0x8D`、`0x8B`）；还原出其依赖速度参数计算计时器配置，但尚未确认电机脉冲与角速度之间的具体标定关系。不能据此把 `00300` 解释成 300°/s、300 RPM 或某个实际加速率。

## 4. 加减速状态机与参数边界

固件同时存在目标位置控制和速度设置逻辑，可辨识连续控制及到位处理函数，但**没有已证明的独立 `AT+ACC=`, `AT+DEC=`, `AT+JERK=` 指令**；对当前镜像的明文 AT 命令表搜索结果中没有这些字符串。自动加减速可能由固件内部离散状态、步进定时器或 PWM 调整完成。仅依据当前反汇编证据，不能定量给出线性加速度、最大斜率或减速曲线，也不能声称已经完全恢复状态机。可靠验证需要对定时器输出/电机脉冲作示波器采样，并对变更速度参数前后进行对照。

## 5. 原生 DEMO / AT+TEST=

`0x3871` 将字符串表偏移 `0x9D57` (`AT+TEST=`) 传入比较子程序；匹配后在 `0x387D` 设置指针 `0x0051` 并调用 `0x8BEE`，随后返回成功值。`0x8BEE` 还由 `0x6B26`、`0x8642`、`0x9686` 等其它逻辑调用，因此**不能把这个匹配动作本身当成已完成的全套巡航算法**。当前没有从此分支独立确认起止角度、速度、往返次数或 DEMO 的帧参数定义；SDK 应保留实验性命令占位，待测试数据而非编造默认参数。

## 6. 其他已查到的固件 AT 文本（不等于已证明可以从 TCP/60020/NRL2 直接调用）

| 类别 | 固件明文命令标识 |
|---|---|
| 网络静态配置 | `AT+IP=`, `AT+GATEWAY=`, `AT+MASK=`, `AT+DNS=`, `AT+PHY=` |
| 动态地址 | `AT+DHCP=ON`, `AT+DHCP=OFF` |
| 服务与身份 | `AT+D_IP=`, `AT+CALL=`, `AT+SSID=`, `AT+S_ID=` |
| 型号/系统 | `AT+YT=3040`, `AT+YT=3051`, `AT+YT=3060`, `AT+YT=YS3051`, `AT+YT=SP5050` |
| 其他参数 | `AT+XW=JX`, `AT+XW=GD`, `AT+P450`, `AT+P360` |
| 速度 | `AT+AZ_SPD=`, `AT+EL_SPD=` |
| DEMO/管理 | `AT+TEST=`, `AT+INIT`, `AT+RESET` |

高风险配置包括网络 IP/网关、身份、行程切换、INIT/RESET；SDK 不得在发现、查询或断线重连时自动发送，必须人工确认并有回滚计划。

## 7. 仍须解决的接口细节及下一轮优先级

1. 逆向 `0x89D9 -> 0x6240 -> 0x3F6B` 的 Socket 0 帧语法、首字节标志、长度、回复编码，确认 TCP/60030 的 AT 完整事务。
2. 完整解码 `0x7652` 的外设/串行队列来源与速率、校验，避免误用不相干接口。
3. 系统地恢复 AT 所有参数：每条命令的数值约束、校验和、写入持久化位置、回读命令与实际返回文本。
4. 用隔离电机电源的 TCP/60030 只读实验确定是否存在状态查询；禁止先发送会改写 EEPROM 的测速命令。
5. 对自动加减速做有界驱动台架采样后，才可能标定速度原始字段与 °/s、加速度单位。
6. 结合支持速度设置的原始厂商 GUI/串口调试协议 PCAP 样本或资料，解决 DEMO 参数语义。

## 8. 可复现证据脚本

`verify_stage5.py` 仅使用 Python 标准库对原版 8051 映像逐字节确认关键代码和字符串。运行示例：

```bash
python verify_stage5.py RC_3040S_67S_8H_251217_firmware_8051.bin
```

对指定 SHA-256 的映像，8 项静态断言通过。此验证不是 8051 完整仿真、TCP 抓包或物理运动测试。
