# 网关健壮性审查：TCP 超时与 UDP 身份作用域

对应固件版本和协议背景参见 [stage 8](RC3040S_stage8_APK_DEMO_compatibility.md)。
本次是 SDK/Host 安全边界加固，不声称改进了设备固件原生协议。

## 发现和更改

原网关在收到一个字节格式正确的 `W/M` 或方向运动请求后，会先建立
TCP/60020 连接，**再**检查 `(APP SID, UDP源地址:端口)` 的 C2 新鲜度。
无权移动的 UDP 端点仍能诱发 TCP 建连，构成连接滥用点。

修正后按以下顺序：

1. 字节级 NRL2 Type5 解析与 GS-232 白名单。
2. 区分只读查询、STOP、有限目标定位，丢弃其它命令。
3. 对目标定位先查 `(SID, UDP来源端点)` 与近期位置读回，再按机械角度上限过滤。
4. **仅当已通过权限与限位判断**才建立与硬件的 TCP 会话。
5. 每次 TCP 操作独立时间窗；超时产生 `TransportFailure(TimeoutException)`，
   保持 UDP 网关主循环运行。单次 TCP 断连或未应答不可使整个网关退出。
6. STOP 从不因缺少历史查询而被拒绝，但仍是 best-effort TCP 写操作，不能替代物理急停。

## 测试

Loopback 测试故意令模拟控制板对第一条 C2 不响应、超时，再用第二次连接返回
模拟角度，以验证服务持续存在。另一个测试来自 stage 8：不同 UDP 源端点
即使复用相同 SID 也不能继承运动资格。

该协议本身未验证任何网络鉴权与重放防御。此处的端点绑定只减少意外共享，
**绝不是身份认证**。禁止在不受信任网段直接暴露运动 UDP 入口。
