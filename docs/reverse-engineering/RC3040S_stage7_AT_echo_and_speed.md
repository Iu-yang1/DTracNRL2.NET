# 第七阶段：AT+TEST 回显、速度诊断格式与电机计时器

**来源**：用户提供的 RC-3040S STC8H 251217 固件恢复的独立 8051 ROM；SHA-256
`59f5114c0289fb0f273aba50b5987688a27bf88e1034a577a38c46bb45ba019f`。
**类型**：离线机器码交叉验证，不涉及联网、不向云台写入或驱动电机。

## 1. 消除 AT+TEST= 与 DEMO 的误关联

- `0x3871` 用 `AT+TEST=` 字符串进行命令匹配；匹配通过后 `0x387D` 设三字节指针 `01:0051`。
- `0x5CE1–0x5DB7` 把传入的 AT 文本复制到 XDATA `0x0049` 开始的命令缓冲区；`0x0051` 距缓冲区起点偏移八字节，恰好跳过 `AT+TEST=` 八字符前缀。
- `0x3883` 调用 `0x8BEE`，保存待发送的源指针；`0x8C14` 调用 `0x8A1F`。
- `0x8A1F` 经过 `0x982D` 求字符串长度，`0x8A5E` 固定 `R5=1` 再进入 `0x58C9`。
- `0x58F0` 将发送帧 opcode 与 `0x80` 作或运算，构造文本帧。后续 `0x977C` 选择通信发送端。
- 因此最可取的静态解释为 **echo diagnostic over WebSocket**，而非已确认的原生巡航运动序列。真实回显是否保留终止符、是否伴随其它状态帧，仍需要授权抓包验证。

已更正 SDK 接口：`DiagnosticEchoPrefix`、`DiagnosticEcho(text)`。
历史上不准确的 `DemoCommandPrefix` 仅作为标记为过时的兼容别名保留。
**绝不以 AT+TEST= 控制真实电机巡航。**

## 2. 原始速度参数、定时器计算

- `0x3BEC→0x720E` 从命令偏移 10–14 解析五位 AZ 数字，`0x3C14→0x720E` 解析 EL；
  `0x3BFF/0x3C27→0x9500` 触发参数保存，随后进入 `0x7A44/0x7ABB`。
- `0x7A44` 从 XDATA `0x09A3..0x09A4` 取得存储的 AZ 参数，拷贝到 `0x102A..0x102B`；`0x7ABB` 从 `0x09A5..0x09A6` 拷贝到 `0x102C..0x102D`。两者调用共同定点除法/乘法辅助例程 `0x8A63`，最后写入芯片计时器寄存器（AZ `0x8D/0x8B`，EL `0xD6/0xD7`）。
- 初始化路径 `0x8BDC→0x7A44`、`0x8BDF→0x7ABB` 再应用持久化参数，佐证这些不是单纯的临时内存变量。
- ROM 字符串 `0xA0DF` 和 `0xA101` 分别使用 `AZ SPEED: %05u  HZ , %02f `、`EL SPEED: %05u  HZ , %02f `，紧跟 `/s\r\n`。因此至少一个字段明确以 **Hz** 呈现；后面的 `/s` 未见经验证的单位前缀，不得换成 °/s。
- SDK 可以**解析已经收到的诊断消息**，但该操作不能证明设备已执行 AT 写入，也不能把频率映射为机械速度。

## 3. 自动加减速与原生 DEMO 的证据缺口

目前没有从这一 ROM 确认可写的 `ACC`/`DEC`/`JERK` 指令；计时器装载值的设置不等于已完成自动加减速状态机建模。固件对目标角度的闭环更新、到位减速的具体条件、响应时间与机械减速比仍需更深层控制流与实机电机脉冲采样。上层 `DemoCruise` 是 SDK 软件规划器，**不是**固件 `AT+TEST=`。

## 4. 接下来必须用硬件验证的事务

1. 在电机功率隔离下连接 `ws://<device-ip>:60030/`，保存握手及主动消息的原始字节。
2. 先观察不发送命令情况下的状态字段及 WebSocket Ping/Pong；不能将 `welcome` 或网络发送成功当成 AT ACK。
3. 在确认硬件恢复路径和配置备份后，再有限次测试 `AT+TEST=` 是否回显字符串。
4. 对速度配置读写需先恢复返回错误码与读取入口，再标定 Hz 与电机轴角速度的映射；确认非易失写入限频。
5. 实现原生 DEMO 必须找到另外的真实固件入口和状态转移，不能引用 `AT+TEST=` 充数。

## 5. 复核样本及约束

可执行 `scripts/verify_firmware_stage7.py` 对 SHA 固定的固件逐字节检查 `AT+TEST=` 路径、WebSocket 文本发送、两个速度应用函数和诊断字面量。该检查不操作设备。
