# 第十阶段：AT+CALL / AT+SSID 设备身份配置与 AT+D_IP 转发目标路径

对象：SHA-256 `59f5114c0289fb0f273aba50b5987688a27bf88e1034a577a38c46bb45ba019f`
的 RC_3040S_67S_8H_251217 8051 ROM。以下均为静态控制流分析。

## 1. AT+CALL= 的可辨认范围

`0x38F4` 对字面量 `AT+CALL=` 进行比较，匹配后的 `0x38FC..0x395E` 在 XDATA `0x0723/0x0724` 维护
16 位计数值，将缓冲区 `0x0051 + index` （跳过八字符前缀）逐个复制到
`0x09E2 + index`，在相邻地址补零终止，遇到 CR、LF、NUL 提前退出。
`0x390B..0x3912` 将计数器与 **6** 比较限制循环。退出后调用 `0x8CE7`
执行配置保存。实际接受更长字串时是截断、拒绝还是覆盖风险，需要实机验证。

SDK 的 `SetCallsign(string)` 因此只允许 **1..6 个大写英文字母或数字**，
这是更严格的安全编码子集；不代表固件自行拒绝全部其他字符。
本字段不能作为身份认证，也不等于 NRL2 包里的原始 7B RotorID。

## 2. AT+SSID= 的单字节配置格式

`0x3966` 匹配 `AT+SSID=`；`0x3975..0x3993` 根据入口模式
比较带 CR/CRLF 的字符串总长度是否为 12/13 字节（前缀 8 + 数字 3 + 结束符），
`0x3995` 设置 `R7=8` 后调用十进制三位解析函数 `0x8E76`，
`0x399A` 将返回值写入 XDATA `0x09E1`，`0x399F` 调用 `0x8CE7` 保存。

因此字节编码为 `AT+SSID=003\r` 或其他 **3 位 ASCII 十进制字节**。
固件的配置字段名 SSID **不能据此理解为 Wi-Fi 服务集名称**，
它仅在本固件映像中代表一字节身份设置。

SDK 实现 `SetDeviceSsid(byte)`；不提供超出 0..255 的“猜测扩展”。

## 3. AT+D_IP= 与 Socket 7 的关系

`0x3AAB` 匹配 `AT+D_IP=`，`0x3AB3..0x3B14` 逐字符
复制后缀到 `0x09F1 + index`，到 CR/LF/NUL 截止；然后调用
`0x8CE7` 保存，`0x96EF` 切换控制状态，设置 `0xC7 = 0x20`。
该行为与远端服务地址配置吻合，但现阶段尚不能完整确认
字符串最大长度、接受 IP/域名哪几种格式、DNS 重试行为或何时断线重连。

**没有足够证据可安全暴露任意长度的 AT+D_IP 写入 API。**
后续需继续定位该配置的读取、网络连接重建及返回错误码。
为避免将控制板与现有网络永久断开，本阶段只记录字节级分析，不默认提供写入。

## 4. 使用边界

- `AT+CALL` 与 `AT+SSID` 是非易失配置操作，不是 GS-232；目前需要 WebSocket/TCP60030 管理路径，且未有真实硬件 ACK。
- 所有公开 API 都只是受边界约束的命令构造器，必须由操作员显式确认才会发送。
- 此分析不证明设备的密码、安全认证、配网恢复操作或公网协议。
- 相关样本与加密密钥、真实设备 ID 不包含在源码仓库中。
