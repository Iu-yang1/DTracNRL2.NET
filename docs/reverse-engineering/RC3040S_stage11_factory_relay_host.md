# 第十一阶段：固件出厂配置、AT+D_IP 本地中继地址与端口

固件样本 SHA-256 `59f5114c0289fb0f273aba50b5987688a27bf88e1034a577a38c46bb45ba019f`。
本分析只读取出厂初始化路径 `0x53E0..0x5539`，不调用初始化指令、不连接云台。

## 1. 默认服务地址存放位置

在 `0x552C..0x5533`，固件取代码地址 `0x9C33` 并以 `R7=0x50` 调用
配置字符串写入函数 `0x894B`；ROM `0x9C33` 的 NUL 终止文本为：

```text
202.141.176.002
```

**这只是本固件镜像中的出厂默认字符串，不保证当前为有效服务器，也不意味着 SDK 应使用它。**
同时配置初始代码 `0x5521..0x5529` 通过 `0x894B` 写入一个 `NOCALL` 标记。

`0x3AAB..0x3B14` 的 `AT+D_IP=` 分支在配置区
`0x09F1 + index`（偏移相对于 `0x09A1` 正好是 `0x50`）
连续复制参数文本到 CR/LF/NUL 结束，随后调用保存、重初始化相关例程。
因此它与出厂配置字符串使用**相同目标字段**，高置信度表示远端主机目标设置。

厂商 ROM 采用四组三位数字的 IPv4 字符串。SDK 保守地只开放此格式：
`AT+D_IP=192.168.001.050\r`，不暴露任意长度原始写入，以避免超过字段可用空间。
真实目标解析能否识别局域网地址和是否立即生效仍需硬件验证。

## 2. 默认 UDP 服务端口两个配置字

出厂默认初始化对配置偏移 `0x30/0x31/0x32/0x33`
分别写入 `0xEA 0x92 0xEA 0x92`，见 `0x54FE..0x5517`。
两组网络大端 16-bit 整数均为 `0xEA92=60050`。

这与固件已有独立 Socket7 UDP 远端通路吻合，但尚未通过完整调用链证明
两个字段分别代表本机绑定端口与远端目标端口。SDK 将其明确命名为
`FactoryRelayPortValue`（**出厂值**而非已实机确认的目标端口）。

## 3. 与实际局域网 UDP 部署的关系

预期路径：

1. 在隔离测试环境配置 Windows/Linux 本地 UDP 中继（由 SDK `Nrl2LanRelay` 提供），先仅开放只读查询及 STOP。
2. 在电机功率断开且保存设备原始配置后，通过 TCP/60030 的 WebSocket AT 管理通道执行用户**显式确认**的 `AT+D_IP=<本地IPv4>`；此操作会改写非易失数据并可能造成短暂掉线。
3. 通过本地抓包验证固件是否向本地 UDP 目标发送 Type2、目标端口是否为 60050、是否需要 Type1 应答。
4. 未确认 Type2 注册及 C2 查询的双向性前，不进行运动、DEMO、重启或速度写入。

仍未确认远端 UDP 端口的用户配置指令、域名解析、Type1/Type10 应答、控制板以太网重试策略以及配置异常时的恢复。

**注意**：`AT+INIT` 是重建全部默认值的配置重置操作，绝不可将其作为局域网连接故障的自动修复方法。
