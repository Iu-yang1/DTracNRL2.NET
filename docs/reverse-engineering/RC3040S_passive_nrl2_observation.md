# 无控制命令的 NRL2 UDP 实机只读观察器

为核实 RC-3040S 固件 Socket 7 到本地中继的真实收发，无需启动
`Nrl2LanRelay` 的转发行为，可以使用 `Nrl2PassiveMonitor`。

示例，在一台由你控制的 LAN Windows/Linux 主机上运行：

```powershell
dotnet run --project src/DTrac.Nrl2.Host -- --observe-udp 192.168.1.100 60050
```

用主机实际 IP 替换示例地址。工具只绑定 UDP 本地端口、**接收并解析收到的
NRL2 数据报，不执行 UDP Send、不连接控制板 TCP、不向云台发送 C2/S/W/AT**。
默认只显示时间戳、来源端点、方向性长度编码、Type、长度与打码后的来源/目标 ID。
不会打印完整 7 字节设备 ID 或原始包含控制命令的负载。

完整的正式中继行为不能通过单向抓包证明。确认真实 Type 2、发包间隔、
目的端口和报文长度后，仍需双方同步抓包以判断服务端如何响应 Type 1/Type 10
或转发 Type 5。

局域网 IP 配置 `AT+D_IP=` 是单独的非易失写操作，由用户在提前保存旧配置且
具有恢复能力的条件下手动操作；**此观察器绝不会尝试自动设置 D_IP**。

当没有任何接收报文时，该程序不具有混杂模式或旁路抓包能力，只能说明
本机所绑定端口没有收到发往它的 UDP 数据报，不能证明设备没有通信。

注意：该工具没有内置访问认证，非回环监听应配合操作系统防火墙，只在
可信隔离的本地实验网络使用。
