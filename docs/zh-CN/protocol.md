# DTrac NRL2 协议及安全说明

这是基于 DTrac APK 与 RC-3040S 固件离线静态分析的**非官方互操作实现**，不能泛化成所有 NRL2 系统。

## UDP 应用数据报结构

| 偏移 | 长度 | 含义 |
| ---: | ---: | --- |
| 0 | 4 | ASCII `NRL2` |
| 4 | 2 | 两个 ASCII 十进制长度字节，表示帧总长 |
| 6 | 7 | APP SID，二进制 |
| 13 | 7 | RotorID，二进制 |
| 20 | 1 | Type `0x05`，GS-232 |
| 21 | 3 | 零 |
| 24 | 5 | `DTrac` |
| 29 | 19 | 保留零填充 |
| 48 起 | 可变 | GS-232 ASCII 命令 |

`C2\r\n` 长 52B，`W181 030\r\n` 长 58B，`S\r\n` 长 51B。W5500 RX 缓冲前面另有 8B UDP 元信息，因此固件内 Type 位于 +28，GS-232 载荷位于 +56。

## 网络端口区别

- UDP/60059：只用于局域网 `cmd=ping\n` 发现、`cmd=pong` 应答。
- TCP/60020：本地 GS-232 控制路径。
- W5500 Socket 7：经设备配置地址/端口连接 DTrac NRL2 UDP 远端中继，**不能使用 60059 取代远端中继**。

## 功能与证据边界

已从固件代码定位 Type 5 解析到 GS-232 的控制链。角度命令、STOP、连续方向命令的封装与 APK 样本一致。自动加减速由 RC-3040S 固件执行，本库不控制电机 PWM 曲线。PARK 为单次 W 定位，不是机械回零；DEMO 为宿主程序根据及时反馈逐点控制，不是已验证的设备内建巡航。

公网 DTrac 中继的注册、保活、路由及鉴权行为尚未实测；开源 `hicaoc/nrllink` 不可直接视为兼容服务端。实验性 `AT+RESET\r\n` 不会由本库自动发送，远端能否接受亦待核验。**网络发包成功不代表机械动作成功或已经安全停机。** 请保留真实硬件限位、物理急停，先在断电机功率环境做只读测试。


## 推荐：内网直连，不需要私有中继

本 SDK 提供 `Rc3040sLanClient.ConnectAsync("控制板局域网IP", 60020)`，
与 RC-3040S 固件 TCP Socket 3 的 GS-232 解析器通信，不封装 NRL2，不需要 APP SID、RotorID 或 DTrac 公网服务器。

使用 UDP/60059 仅发现控制板；通过 `DiscoveredRotor.Address` 及 `LocalTcpPort`
建立 TCP 直连（建议先只读调用 `QueryPositionAsync`）。固件静态分析显示
`C2\r` 返回预期 `AZ=ddd  EL=ddd\r\n`，未完成实机验收。

- `ConnectAsync` 不会自动运动；
- `QueryPositionAsync` 只执行 C2 只读查询，超时返回 null；
- `MoveToAsync`、`JogAsync`、`StopAsync` 必须显式调用；
- TCP 写入成功不等于机械动作确认；STOP 亦不可替代物理急停；
- 本地 TCP 不提供鉴权，建议在可信 LAN/VLAN 内使用，勿将 60020 直接暴露公网。

如明确需要兼容官方 DTrac APP 的 **NRL2 UDP**，才需研究局域网自建中继，
不能把 NRL2 Type 5 报文直接发往设备的 UDP 60059 发现端口。


## 内置局域网 NRL2 中继（实验性）

`Nrl2LanRelay` 提供与 RC-3040S Socket7 对应的 Type2 设备登记、
Type5 APP→设备转发及设备 Type5→APP 返回路径。
SDK 明确区分 APP 的 **两位 ASCII 十进制长度**与固件发送端的 **BE16 长度**。
设备注册同时验证 RotorID 和明确配置的设备 IPv4 地址，默认不允许转发运动指令。

中继不是 DTrac 私有服务器源码的复制品，尚未验证固件需要的 Type1 应答、
完整认证及公网部署语义。默认建议仅在测试机回环地址监听；如确需 LAN，
请隔离 VLAN/防火墙并严格限制设备 IP 与控制方主机访问。该协议没有确证的
加密和抗重放机制，因此不可将 14 位 ID 当成访问密钥。

### 速度及加减速

固件反汇编在 `0x3BE0..0x3C2F` 中证实 `AT+AZ_SPD=`、`AT+EL_SPD=`
对应数字解析、参数存储及函数 `0x7A44/0x7ABB` 应用速度；而普通
GS-232 命令解析器是 `0x3433`，AT 命令入口为 `0x3863`。
因此目前**不能保证** TCP/60020 或 NRL2 Type5 通道可直接调用这些配置命令，
也不能从该字段推断具体 Hz/度每秒单位和合法上下限。

`Rc3040sFirmwareCommands` 提供仅构造 AT 指令文本的独立 API，
不会自行写入网络。固件自动加减速为控制板内建控制策略；
没有确定独立加速度、减速度参数的可写 AT 命令，不应宣称可以调节
加速度常数。


## 另一种内网 UDP 实现：TCP 转换网关

`Nrl2TcpGateway` 允许本地程序向 SDK 内置 UDP 网关发送 NRL2 Type5，
然后由网关转成 RC-3040S 的原生 TCP/60020 GS-232，
不要求修改控制板的 Socket7 服务器设置，也不需要公网 DTrac 服务器。

```bash
dotnet run --project src/DTrac.Nrl2.Host -- --tcp-gateway 127.0.0.1 19021 123456789ABCDE 192.0.2.10
```

这条通路本质为 **UDP→TCP 网关**，并不是设备 UDP/60059 原生运动指令。
默认只允许查询和 STOP；`--enable-motion` 才开放经过范围校验的绝对定位，
并要求近期真实 TCP `C2` 反馈。无可靠硬件急停看门狗前不转发持续手动方向
指令。所有地址和 ID 均为示例，实际使用需由用户确认机械限位和局域网防火墙。


## 第五阶段固件逆向新发现：TCP/60030 管理通道

在 `0x920C` 识别到初始化 W5500 Socket0 的端口 `0xEA7E` = **60030**，
网络路径可沿 `0x993A→0x912D→0x9157→0x9856→0x89D9→0x6240→0x5CE1→0x5DB7→0x3863` 追踪到
AT 命令解析器。不过中间包含额外的帧类型分支，**当前绝不能向 TCP/60030 直接发送未封装 AT 并假定成功**。
TCP/60020 仍为 GS-232 通道，UDP/60059 仅发现，NRL2 Type5 仍转 GS-232。

`0x720E` 速度解析器以五位十进制固定位置读取 AZ/EL 速度原始值，
因此 SDK 构造格式更正为如 `AT+AZ_SPD=00300\r`。这些数值不能解释为度每秒，
也不是经实机认证的安全速度范围；设置可能写入 EEPROM。详细证据、配置表和待验证项：
[第五阶段 AT 与电机控制逆向报告](../reverse-engineering/RC3040S_firmware_stage5_AT_and_motion.md)。
